## 球速估计

以下为末100轮各轮指标的算术平均，非合并所有样本重新计算的RMSE。日志的velocity误差是三维速度向量误差，包含方向；目标是世界速度旋转到root坐标轴，未减机器人自身速度。

| 分层 | 位置RMSE cm | 速度向量RMSE m/s | 速度误差P95 m/s |
| --- | ---: | ---: | ---: |
| 活动且当前可见 | 12.31 | 0.319 | 0.587 |
| 正在来球 | 47.38 | 0.556 | 1.320 |
| 球心距脚link小于35cm | 109.57 | 0.883 | 1.570 |
| 全部状态 | 170.27 | 0.788 | 1.652 |

因此不能说球速估计已准确，尤其不适合据此承诺精确的触球时序控制。可见位置已有一定精度，近脚/遮挡阶段很差。全部状态还包括等待及球离开视野的样本，不能代替来球阶段的准确率。

独立确定性回放（训练课程，16环境、1000步即20秒/环境）得到来球**标量速率**MAE=0.168m/s、RMSE=0.241m/s，真实平均速率0.855m/s；同一分层速度向量RMSE=0.393m/s。不能把只看速率大小的误差当作完整速度向量精度。该小规模CPU确定性轨迹与4096环境随机训练分布不同，数值不应混为同一统计。

深度打乱采用同一步把整段8帧历史在16环境间循环移位。训练课程中活动可见速度向量RMSE从0.372增加至1.976m/s，说明预测确实依赖深度，而不只是输出常量；此为有限样本诊断，不是完整科研消融。与本体状态的联合输入相关性也同时被打乱，不能将增量解释为纯视觉因果效应。

训练课程近脚样本1057个，其中549个（51.94%）的全部8帧都没有球像素；该盲区层位置RMSE=125.31cm，速度RMSE=0.884m/s。进一步只看近脚且正在来球的373个样本，60.86%全部历史不可见，位置RMSE=89.90cm，速度RMSE=0.924m/s。8帧历史约0.16秒，当前网络没有更长的记忆或显式状态传播；全无球深度产生相同视觉输入，不能恢复任意球状态。

## 为什么播放时几乎不踢

确认存在之前实现遗漏的接口错误：play调用`runner.load(..., load_optimizer=False)`，但runner把课程曝光计数恢复也放在`load_optimizer`条件下。因此默认播放丢失训练进度，重新使用0.5–0.7m近距离、0.4–0.8m/s慢球；训练权重对应1.3–2.0m、0.4–约1.53m/s。

使用**同一个**model_25200、同一种子921、相同16环境和20秒时长，直接切换场景采样范围（同时改变距离和球速，未分离各自作用）：

| 指标 | 恢复训练课程 | 旧默认播放课程 |
| --- | ---: | ---: |
| 运动中的初始球 | 16 | 16 |
| 同episode恢复后发球 | 94 | 72 |
| 踢球成功代理事件 | 92 | 9 |
| 代理事件时最近脚平均速度 | 2.231m/s | 1.359m/s |
| 代理事件脚速<0.2m/s占比 | 0% | 11.1% |
| episode终止/reset | 0 | 0 |
| 全部步骤最大脚速的时间平均 | 0.296m/s | 0.038m/s |

这直接反驳“这个权重完全只学会站立”的判断：在训练课程下有明显足部运动及持续恢复重发。不能将92/94当作成功率，初始16球及窗口结束未完成的球必须计入正确分母；这里只报告次数，也没有真实接触传感器来给全部事件提供足部接触证明。旧播放最后一次代理发生在第169步（3.38秒），其后到20秒末没有新代理事件，能复现之后长时间站着的现象。

训练日志也支持恢复链路已工作：末100轮来球样本平均28.12%、等待23.92%、近脚8.32%；episode平均2897.8步约57.96秒。编码器每轮4次接受更新，平均7.8次被拒绝的试探，无head-only退化。故当前不是旧的零发球或永久KL拒绝问题。

站立仍能得到持续奖励，原始成功检测也允许被动回弹记分；这是后续奖励审查点。但本次恢复训练课程的92个代理事件并非低脚速事件，不能把这次现象直接断言为“全靠站着刷分”。
