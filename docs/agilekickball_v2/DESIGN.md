# AgileKickball-v2：继承 v1，只扩展速度课程

当前 revision=`v1_speed_only_20260925`，checkpoint schema=5。启动打印版本，保存的 `params/env.yaml` 中 startup 参数也包含版本，TensorBoard 有 `AgileV2/schema=5`。旧 schema3/4 checkpoint 不兼容，加载策略权重前直接报错；请从零训练。

## 为什么回到 v1

最新旧 v2 训练到40982轮，最近1000轮平均67.43控制步（1.349秒），恢复后发球累计仍为0，但速度上限已6m/s。同轮数v1平均2186.48步（43.730秒），窗口新增发球中恢复再发占92.71%，上限约1.528m/s。最新run名称虽含stability_fix，实际checkpoint仍是schema3/recovery_envelope_v1，进程没有加载随后写入的schema4修正。不能据此判断未训练schema4的学习效果。

旧v2同时修改固定时钟距离课程、采样和恢复判据。已有回放显示早期策略对距离敏感，坏v2策略换回v1恢复规则也不能立刻恢复；主要失败发生在恢复等待之前。故这次以已经学成连续踢球的v1为基线，撤下v2新增的状态机、采样及未训练的奖励修改，仅改速度课程。独立因果贡献未经从零训练消融证实。

## 完全继承的行为

- v1 的观测、深度处理、辅助监督、动作、奖励、所有终止项、PPO/AMP、网络均保持一致。踢球即时奖励weight=300，return=8，miss=-60，与v1相同。
- `reset/tick/_serve/_sample_serve_speed/balanced/_ready_to_serve` 直接继承，没有 v2 重写。包括发球随机数抽取顺序。
- 球结束后等待；连续身体稳定0.3秒且至少等待0.4秒，才重发球。只移动球，不重置机器人。等待满5秒仍未恢复则终止。终止中的环境不能重发。
- 初始/失败重置采用v1站姿和发球。恢复判据使用v1身体倾角、线/角速度、身体高度、双脚高度、关节速度有限值；不加新的锚点门限或扰动峰值门限。
- 距离按平均真实来球曝光 E 从0.5–0.7m线性增至1.3–2.0m，E=60000封顶，与v1相同；取消按总训练时间推进距离。

## 速度课程

E 是所有环境平均的来球控制步数，包括存档曝光；不是所有并行样本数之和。控制周期0.02秒，默认每轮PPO收集24步。

1. 基础阶段：速度均匀采样 `[0.4, 0.8+1.2×min(E/240000,1)]` m/s。与v1的0.8→2.0阶段完全一致。没有连续恢复能力时，最多慢慢到2.0，不按时钟强推6.0。
2. 每至少6000控制步（约250轮）测量一个窗口。只有窗口新增发球数≥128、E≥60000、恢复后发球份额≥0.8、kick代理份额≥0.6，才解锁快速扩展。初始窗口包含初始化发球；后续按累计计数差分。
3. 解锁上限记为U0（1.1–2.0m/s），有效扩展进度P从0开始：`U=U0+(6-U0)×min(P/288000,1)`。不补算解锁前的控制步。
4. 每个新窗口确定后续推进倍率：`r=clip((恢复份额-0.5)/0.3,0,1) × clip(kick代理份额/0.6,0,1)`；`P += 控制步增量×上一窗口r`。恢复≤50%、没有kick代理或样本不足均暂停继续提速；当前速度上限保持，不回退。满倍率需要12000轮扩展到6m/s，实际取决于学习表现。
5. 全程均匀采样 `[0.4,U]`，保留慢球复习，不引入分箱采样或强制高速挑战。上限6时约17.9%来球速度>5m/s。

窗口份额是“新增恢复发球/新增总发球”和“新增碰撞kick代理/新增总发球”，不是同一球的严格踢回+恢复成功率。分子和分母跨窗口的未结算球会让代理份额略超过1，原值保留用于诊断，门控值限幅。低速的表现也会影响全范围统计，不能把上限6解释为已经掌握6m/s。

课程仍由v1 reset-time callback更新。记录metrics不额外改课程；保存checkpoint与v1一样同步一次。同一步重复同步不重复积分。全体环境长时间没有reset时，下次同步才应用新范围；当前场上球不被重新加速。

## 存档和播放

保存曝光、控制步、解锁状态、起点上限、有效扩展步、倍率及最近窗口诊断。resume重新绑定当前环境时钟和计数器，丢弃未满的部分测量窗口，保留最近倍率直到新窗口测量；其余恢复行为沿用v1。支持更换环境数量。play冻结课程状态，`--ballspeed min max`只覆盖实际发球范围，不写回训练进度。

关键图：`AgileV2/schema`、`extension_unlocked`、`speed_upper_m_s`、`advance_rate`、`recent_recovered_serve_share`、`recent_kick_proxy_share`、`recent_serves`、`extension_progress`。同时看mean_episode_length和恢复发球计数；不要单看mean_reward或球速上限。

## 启动

```bash
python scripts/rsl_rl/train.py \
  --task Template-Perceptual-Ball-AgileKickball-v2 \
  --num_envs 4096 --device cuda:0 --headless \
  --max_iterations 50000 --seed 42 \
  --run_name v1_speed_only_20260925_scratch
```

不添加`--resume`。代码更新不会改变已经启动的训练进程。当前未自动启动长训练。
