## 修正内容

### 来球距离跟随实际采样速度，不再随训练时间强制拉远

每次真正发球先采一次速度v，再使用：

`extra = 0.3 * clip(v - 0.8, 0, 5.2)`

`distance ~ U(0.5 + extra, 0.7 + extra)`（米）

0.4–0.8 m/s始终在0.5–0.7 m发出；1.45 m/s在0.695–0.895 m；6 m/s在2.06–2.26 m。晚期的慢速练习球仍保持近距离，高速球有相应的观察和反应距离。速度只采样/计数一次，父serve距离采样和实际写入的速度使用同一批样本；只重置对应环境的球。

### 保留高速覆盖，降低尚未恢复时的挑战负担

速度探索上限保留原节点（24控制步/轮）：0–5000轮0.8m/s、15000轮2m/s、30000轮5m/s、35000轮6m/s。节点间线性推进，下限0.4m/s。这只是探索上限，不是学会该速度的承诺。

r为已有闭合样本的速度箱严格联合成功EMA的等权平均：

- 挑战比例 `0.05 + 0.45*r`，采样探索上限末端1m/s区间。
- 全范围覆盖比例 `0.10 + 0.10*r`。
- 剩余样本在经验掌握前沿附近练习（原6箱、至少128闭合样本且EMA>=0.65的连续箱规则保留）。

未学会恢复时，85%样本优先练习、10%全范围、5%挑战；联合成功率提高后逐渐增加挑战。到达6m/s上限时，即使r=0仍有至少5%的5–6m/s挑战，加上全范围采样中的高速球。`empirical_mastered_upper_m_s`与`speed_upper_m_s`必须分开解读。

### 恢复回到v1的简单规则

- 球结束后才开始累计连续稳定时间，固定0.3秒；不再使用扰动峰值改变窗口。
- 球结束后至少等待0.4秒，当前身体平衡且未终止，才发下一球。
- 等待恢复达到5秒则结束episode；这5秒从球结束后算，球仍在飞出时不会因此被终止。
- 保留v1身体高度、倾斜、根速度、角速度、脚高度、关节finite条件；anchor约束与原0.6m离锚点终止一致。
- 踢球起的恢复elapsed和扰动峰值仍保留作诊断。联合恢复CDF的时间从主动kick开始计，因包含球飞行阶段，联合成功也可能超过5秒；它不再等于硬timeout预算。tau=0.5/1/2/5s分别统计满足该预算的联合成功数/所有closed球数。

### 奖励与连续任务成功一致

保持v1的观察、动作、网络、PPO、AMP及辅助深度监督。v2专用奖励改变如下（RewardManager会乘step_dt=0.02；当前任务在AMP混合中的权重0.75）：

| 事件 | 配置权重 | 环境脉冲奖励 | 混合后的任务贡献 |
| --- | ---: | ---: | ---: |
| 主动足部回踢 | 100 | +2 | +1.5 |
| 同球主动回程>=0.5m、恢复并再发 | 400 | +8 | +6 |
| 非正常时间上限的episode失败 | -400 | -8 | -6 |

失败包括离锚点、倾倒/跌倒、自碰和恢复超时；纯episode时间上限不罚。原miss惩罚保留。即时踢球奖励仍保留，避免把全部探索信号延迟到恢复之后。严格主动回球仍是运动学代理：原冲量/回球方向条件 + 脚距球<0.3m + 脚相对根沿向外方向速度>0.5m，并非真实接触力判定。

原始碰球代理只作诊断，`kick_proxy_successes`每球只记第一次；被动反弹不再标记为已主动踢球、不获即时或回球速度奖励，球结束时仍会计miss。联合成功脉冲必须保留经过同tick的重新发球，下一有效tick才清零；终止优先，不会失败同时获联合成功奖金。

回球速度奖励只在严格主动候选成立后支付。准备期站立奖励仅在球距机器人XY小于0.8m时降为原来的0.25；球较远时保持完整站立奖励，避免鼓励冲过去追球。恢复期保持完整站立奖励。

## 统计、checkpoint与验证边界

保留按速度分箱的closed/success/failure/censored、联合恢复CDF、连续成功streak和实际>5m/s发球计数。人工reset不能当成功，`served=closed+censored+open`。联合成功和即时踢球均使用单tick脉冲，重复tick不能重复支付。

本修正版拒绝旧v2 schema3以及v0/v1 checkpoint的直接加载，在读取模型权重之前给出不兼容提示。从零训练，不加resume。修改后的checkpoint仍支持自身resume、不同环境数量及冻结play；`--ballspeed min max`、`--visray`仍可用。旧版checkpoint可用归档代码分析，不应直接续训到新任务。

最新验证在 `stability_fix_20260924/validation`。它包括状态机/奖励/距离/checkpoint回归、真实CPU16环境4次PPO更新、成熟v1与旧v2坏策略在相同分布下的奖励排序、6m/s实际物理来球相机覆盖。短测验证流程与奖励方向，不证明从零训练一定稳定或已经学会高速。旧自适应窗口的论文候选目前缺少支持，不作为本修正版的已验证贡献。
