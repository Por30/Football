# v2 与 v1 稳定性审计（2026-09-24）

结论：当前 v2 明显退化，已经学到主动踢一脚但随后跑离锚点，尚未形成连续回球。不能把原因简单归为球速高或恢复窗口短。最值得修正的是前期发球距离/课程与即时踢球奖励之间的配合；恢复窗口自适应也几乎饱和，尚未显示所期待的作用。现有证据不能给各个训练改动分配严格的独立因果贡献。

本次只读检查保存参数、日志及既有 checkpoint，执行 CPU 推理对照。没有改动生产代码、停止/重启训练或更新策略权重。

## 哪些改动有问题

### 1. 发球距离跟着固定时间走，早期难度被同时改变

v2 并非只提高速度。`mdp/agilekickball_v2.py` 的 `_sync_course` 在120,000控制步（5,000轮）把距离从0.5–0.7 m拉到1.3–2.0 m，完全不看是否已学会连续回球。v1 约5,000轮时按实际曝光推算距离仅约0.78–1.16 m。

v2 在3,000轮时上限仍是0.8 m/s，episode已只有1.10 s，恢复后发球为0；同阶段v1已约5.49 s。因此恶化早于速度上限增长，不能把主要原因归于1.4 m/s或未来5–6 m/s。

距离变远而大量样本仍是慢球，使机器人需要等更久。准备期站立奖励沿用v1的0.25倍率、接近和即时回球奖励也未改变，这些项在更远的发球条件下可能鼓励向球冲过去踢，而没有学到刹停。此处是代码与轨迹支持的机制解释，不是完成训练消融后的因果证明。

### 2. 指标要求恢复，但奖励仍在踢球瞬间发放

v2 的严格候选、0.5 m回程和恢复成功只影响统计与采样。`kick_bonus` 仍由原 `kick_success_flag` 当步支付，恢复失败不会撤销之前奖金。离开锚点直接reset，也没有新增对应的终止负奖。miss_penalty仅在球自然结束且尚未踢过时支付，不能处罚“已踢球、随后机器人跑出界”。

这是 v1 已有奖励风险，被新的训练分布放大；不能说v2修改了奖励数值。现在策略高频获得单次踢球信号、每约1.2s结束一集，而严格闭环成功为0。回放表明大多数当前v2碰球满足足部接近和相对向外运动代理，不能简单称其为躯干碰撞或完全不会踢球。

### 3. 自适应窗口几乎一直到上限，课程没有根据失败收敛

当前训练 required_hold_mean约0.3956 s、归一化峰值扰动约14.89；公式在峰值达到4时已经饱和到0.4 s。峰值从发球开始累计且不衰减，踢球/探索过程容易把本回合窗口锁在上限。这使自适应设计几乎退化为固定0.4 s，比v1的0.3 s更严格。

不过当前v2等待恢复仅约0.016%，恢复超时日志为0，主要在约1.2s时离开锚点；回放也显示直接换回v1恢复规则不能修复已训练出的行为。因此窗口饱和是设计问题，但现有证据不支持它是当前失败的主要直接原因。

5s恢复截止从kick开始（v1从球结束后开始）会缩短可用余量，也应单独检验；当前主要失败发生得更早，不能把所有失败都归为这个计时差异。

课程上限按时间推进，经验前沿和联合成功不达标只改变部分采样。高速度曝光被保证了，稳定技能未被保证。不能再把“3.5万轮到6m/s”解释为能自动走出当前失败模式。

## 相同策略、相同来球条件的反事实回放

完整结果为 `replay.json`。CPU16环境，每条件800控制步，seed=924，确定性策略推理；固定速度0.4–1.45 m/s，通常距离1.3–2.0 m。直接加载既有策略权重，仅切换环境state/恢复规则；不训练，不修改文件中的正式配置。每条件物理仿真16s，不能作为长期或多种子训练消融。

- v2第10,400轮策略：使用v1恢复规则，226次episode终止、0次恢复后发球；使用v2恢复规则，同样226次终止、0次恢复后发球。主动足部代理分别233和229次，说明会踢但不能恢复连续进行。
- 成熟v1第47,400轮策略：v1恢复规则113次恢复后发球，v2规则115次；v2规则中没有episode终止。说明v2运行时状态机能服务一个已经稳定的策略，但不能证明其从零训练过程合理。
- v1第10,000轮策略：在v2恢复规则下，将距离由1.3–2.0 m缩至0.5–0.7 m，episode终止由66降到14，恢复后发球由34增到113。说明早期策略对距离非常敏感，支持优先修正距离课程。
- 当前v2策略改短距离后仍0次恢复后发球，已学到的坏行为不能靠play改参数立刻恢复；修正训练目标与起步分布后要重新验证学习。

“恢复后发球”只要求身体恢复，可能接在miss之后，并不等于严格主动回球联合成功；上面这些数值仅用于验证恢复流程/连续运行能力。

## 修正优先级（本次未实施）

1. 恢复可靠的近距离起步，让策略先学会踢完刹停和连续接球，再扩大距离；速度与距离不要一起按固定时间推进。
2. 保留即时踢球学习信号，同时给恢复并准备下一球分配奖励，并显式处理离锚点/跌倒失败；避免把全部奖励延迟到恢复后，重新造成稀疏奖励。
3. 先用v1固定0.3s身体稳定窗口建立对照；将新稳定性指标保留为诊断，不急于把未经验证的自适应门槛和采样耦合成多项同时变化。
4. 高速继续作为挑战样本，但主训练分布以连续回球能力为依据；当联合成功长期为0时，不能仅凭时间不断增加难度。
5. 校正峰值饱和后再以匹配速度/距离和多种子从零训练验证自适应恢复是否有益。论文候选贡献目前没有得到训练证据支持。

上次47项回归、一次PPO更新和成熟v1策略回放只证明工程路径可运行，没有验证从零训练能否形成连续技能。对这次大幅改变课程与恢复的任务，验收不足；不应据此对高速学习效果作承诺。不建议把当前运行原样跑满50,000轮当成可靠补救。用户当前运行仍保留，等待后续具体修改/运行指令。
