# AgileKickball v4：回传给发球者

当前版本 `return_to_sender_20261012`，任务 `Template-Perceptual-Ball-AgileKickball-v4`。

以稳定 v3 `feedback_stable_20261008` 为基础，每轮保存实际发球点 world XY 和初始来球反方向。在发球点设置与来球方向垂直的目标门；球经过脚部击球后，需要从机器人一侧反向穿过该门。这里的“原路踢回”具体落实为回到本轮发球点附近，不要求反向轨迹的每一个点完全重合。

| 项目 | 当前配置 |
|---|---|
| 发球距离 / 来球横向偏移 | 1.3–2 m / ±0.25 m，与稳定 v3 相同 |
| 发球角度 | 相对机器人初始朝向 ±0.35 rad |
| 球速课程 | 从 0.4–1.1 m/s 重新起步，沿用恢复门控，最终 0.4–6 m/s |
| 机器人活动半径 / 球结束半径 | 0.6 m / 3 m |
| 目标门半宽 | 初始 0.6 m，最终 0.2 m（完整门宽分别 1.2 m / 0.4 m） |
| 门宽收紧门槛 | 最近窗口至少完成 128 轮，当前门命中率 ≥60%，原恢复发球份额 ≥80% |
| 方向课程 | 每 6000 控制步评估，累计 120000 个允许推进的控制步线性收紧；不达标暂停 |
| 每轮容差 | 发球时冻结，课程变化只影响后续发球 |
| 击球证据 | 球速度跳变 >0.15 m/s，最近脚到球中心 <0.30 m；是代理，非接触力真值 |
| 严格门命中 | 本轮曾有效脚击球、单向过门、正向速度 >0.4 m/s、横向误差合格、插值球高 0–0.35 m、机器人本步未终止 |
| 初始化 | 完整加载最新 v3 `model_49999.pt`，包括预测头、反馈分支、归一化、动作标准差和 AMP |
| 训练 | 4096 环境，50000 次迭代，seed 42，PPO 初始 lr=1e-5，辅助 lr=1e-4 |

网络、观察形状、辅助梯度隔离、反馈限幅、AMP 和姿态/恢复正则项保持 v3 设置。发球点只用于训练奖励和统计，不进入 actor 或 critic。策略通过原有本体/深度短历史感知来球轨迹；没有增加任意独立传球目标输入，也不宣称短历史在所有遮挡场景下足以恢复发球点。

## 奖励

- 朝发球点的方向质量：根据当前速度外推到目标门的横向误差，使用高斯形状权重，并乘以朝向发球点的夹角余弦正部分。只有朝源点外侧的速度 >0.4 m/s 且目标门还在前方时有效。
- 原 `kick_return_task` 改为该质量乘正向速度（限幅 3 m/s 后除以 3）。只有本轮脚击球后 0.5 s 内、首次过门之前有效；权重仍为 8，每轮最多 4 个原始任务奖励单位。
- 原 `kick_bonus` 保留 300 权重，但需脚击球资格，数值变为 `0.2 + 0.8 × 方向质量`。50 Hz 下最多支付 6。保留 0.2 的基础击球奖励，帮助从原技能过渡。
- 目标门真实命中额外一次奖励，权重 150，50 Hz 下支付 3。
- 球结束时未命中当前目标门，`miss_penalty=-60`，50 Hz 下扣 1.2。

以上为 AMP 混合前的任务奖励。原有径向 kick proxy 仍单独用于原球速课程，不当成回传成功。目标命中用相邻控制步之间的线段插值，防高速跨门漏计；每轮首次过门后不再给方向稠密奖励，避免重复往返刷分。

## 统计和 checkpoint

`AgileV4/completed_target_hit_rate` 只用已完成轮次中的当前门命中数作分子，分母包含球自然结束和机器人 reset 结束的轮次。`AgileV4/completed_strict_20cm_hit_rate` 始终按固定 ±0.2 m 门宽统计，用于跨课程阶段比较。未完成轮次的即时命中另记 `target_hits` / `strict_20cm_hits`，不得与完成轮次混合计算比率。完成轮次中的脚击球数也单独记录。回传成功与恢复站稳是不同事件。

v4 使用独立 `agile_v4_return_curriculum` checkpoint key。v3→v4 必须显式 `--warm_start_v3`，PPO/辅助/AMP 优化器、迭代计数、辅助更新计数及两项课程重新开始，来源路径/iteration/SHA256 写入 `initialization.json`。普通 `--resume` 禁止跨任务版本。
