# Wall4 不收敛排查与当前任务设计

2026-10-14按用户要求停止正式训练PID2307414及等待器2300674，状态为STOPPED_BY_USER。最后完整日志iteration14695，保留整个run和最近model_14600.pt。没有重启训练，本轮只有离线分析和不更新参数的仿真回放。

**主要问题是跨回合跌倒惩罚泄漏，策略退化为尽早终止，进而失去AMP有效窗口。** 该奖励错误已作wall3/wall4专属修复；动作范围/拾取参考姿态不匹配也已量化，但未在本轮调整控制范围或重新训练，不能宣称修复后已经收敛。

## 证据和已修复问题

本机Isaac Lab的TerminationManager保留`_term_dones`用于记录最近回合的终止原因，reset不清除它，`get_term()`返回的是这份历史标记。原`mdp.is_terminated_term`直接使用历史标记，只排除当前timeout，没有检查当前`terminated`。因此一旦跌倒，下一回合即使正常存活，也会每步收到`-10×0.02=-0.2`惩罚。

当前`mdp/carrybox_walled.py::failure_event`改为：

```text
(fell历史标记 OR tipped历史标记) AND 当前terminated AND NOT 当前timeout
```

只在当前失败transition处罚一次。没有修改系统IsaacLab、足球或CarryBox-v0基线。wall3/wall4环境契约revision从3升到4，明确记录failure_reward=current_transition；checkpoint schema仍为2。旧正式模型不能按相同环境契约直接resume，也不应被当成健康的初始化策略。

原错误的每步-0.2大于普通接近/伸手奖励；完整AMP窗口额外奖励上限只有0.01/步，任务部分还会乘0.75。于是缩短回合会减少累计负奖励。`Episode_Reward`日志再除以固定20秒，而不是实际回合长度，不能把该曲线上升理解成动作改善。

全部日志的成功统计最大值为0。最后1000轮中64.4%的PPO迭代完全没有有效AMP样本，判别器更新被跳过。AMP=0在这里主要表示没有完整窗口，不能直接解释为判别器认为所有动作都不像专家。辅助位姿损失下降也不表示搬箱能力提升。

## 第二项明确不匹配：动作目标范围

当前29维action经±5裁剪，位置目标为`q_default+0.25*action`，每个关节只可表达默认角±1.25rad。按本机实际默认关节角、按名字映射17段原始动作，三段pickUp分别有20.83%、29.78%、49.61%的帧至少一个关节超出这个目标范围；最大所需|action|分别7.66、8.84、8.62。主要是髋pitch、膝，后两段也涉及左肩pitch。loco和carry参考未出现此项超限。

RSI会直接把关节放到这些拾取姿态，但接下来的策略目标无法完全表达它们。这是控制目标范围不匹配，不是关节顺序映射错误，也不等同于证明这些角度超过机器人物理限位。证据见[参考动作覆盖统计](reference_action_coverage.json)。本轮只改奖励门控，没有同时放大动作范围或调一组新奖励，以免混淆验证。

## 当前wall4实际设计

任务是深度找箱→接近→双手接触→抬起并保持；无搬运目的地、无放下阶段。继承链为本地CarryBox-v0→wall3→wall4。

| 部分 | 当前实现 |
|---|---|
| 控制 | G1 29DOF位置PD，物理dt=.005秒，4倍decimation，50Hz策略；action scale=.25、clip=±5 |
| 场景 | .30×.30×.25m、1.125kg箱子；.2×8×3m墙距root3–4m；三个r=.15m、h=1.8m柱距root2.2–3.2m；平台支撑pickup |
| 碰撞 | 墙/柱/平台六轴锁定且禁重力，真实可碰撞；本机GPU兼容实现。G1四个肩碰撞圆柱为同尺寸32边凸包，visual及共享USD未改 |
| 相机 | G1模型D435名义位姿：torso局部(.0576235,.01753,.42987)m，约47.6°下俯；48×27、垂直FOV58°、光轴深度.1–3m、50Hz，RTX真实遮挡 |
| 传感扰动 | 安装±5mm/±2°；深度噪声σ1cm；延迟0–2步；1%概率冻结1–3步，标签同步配对 |
| actor/critic | 都只读本体4帧93×4=372及深度4×27×48。CNN128维，与本体拼成500维，各接256→128 MLP；actor输出29，critic输出1 |
| 本体93维 | 角速度3×.25、重力方向3、关节相对默认角29、关节速度29×.05、上一动作29 |
| 位姿辅助头 | 深度latent→128→9，预测相机ROS光学系xyz+旋转6D；位置MSE＋D4箱体对称旋转损失，权重.5。真值仅作监督/奖励/reset，绝不作为actor/critic输入 |
| AMP | 根findbox共17段、4628帧，60→50Hz；10×64=640维（q29、qdot29、重力3、body角速度3），只进判别器/风格奖励；专家loco/pickUp/carry=40/40/20% |

| RSI | loco/pickUp/carry=80/15/5%，组内随机片段随机帧；源数据没有箱子四元数，非loco箱姿以root yaw直立代理，平台高度从contact_index估算 |

基础奖励：approach +1、reach +2、接触后lift +6、成功一次+100；action rate -.02、joint acceleration -1e-7、torque L2 -1e-5、关节限位-5；当前失败事件-10。上述均由RewardManager乘dt=.02。

继承wall3奖励：held双臂超阈速度平方（阈1rad/s、权重-.02）、超阈加速度平方（20rad/s²、-2e-5）、waist yaw相对默认角L1（-.5）。held门控为箱心高>.55m且双手中心距箱心<.15m。未接入力矩1.5倍阈值惩罚。wall4搜索奖励权重+.5，仅search且bearing误差>45°、距离>.7m，值为`.7*exp(-.75*abs(error))+.3*tanh(max(sign(error)*body_yaw_rate,0))`。无专门避障奖励。

成功：双手与箱接触均>1N、箱体最低点离地≥.12m、upright>.9、箱速<.25m/s，连续保持.5秒；成功只统计和奖励，不立即重置。终止：20秒超时、有符号roll>.5、|pitch|>1.1、root z<.2m或head z<.4m；非法数值直接报错。roll并非绝对值，这是按用户原说明实现，尚未验证该非对称门槛对G1的合理性。

## 与X2成功任务的关系及后续顺序

当前没有X2父任务源码/启动配置。此前按用户文字移植了墙柱、搜索、yaw课程和附加惩罚，基础walk/pickup奖励却沿用了本地G1 CarryBox-v0，因此不是X2成功配方逐行复现。用户已被询问原项目路径；未获得前不能声称完全一致。

明确差异还包括：X2说明有特权critic，本地按用户要求actor/critic都无特权；X2是其finetune继承链，本地这次明确从头初始化29关节策略，X2实际使用什么预训练checkpoint仍需核实；X2 ray-cast变为本地RTX；相机安装、机器人动力学和接触面不同；本地没有putDown专家片段，box姿态/平台是G1数据适配假设。

恢复训练前应先解决拾取参考与动作目标范围一致性，并校验实际关节限位/PD；验证站稳与行走、参考动作动态可跟踪后，再分阶段检查接近、双手抓取、抬起保持，最后加入wall4搜索及姿态课程。后续学习健康检查必须同时观察真实寿命、失败事件、AMP有效样本和任务成功，不能只看进程与checkpoint。当前正式训练保持停止；奖励bug修复不等于旧策略自动恢复，也不是新的收敛结论。
