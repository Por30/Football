## 已定位问题

**优先修复的明确坐标语义错误：头部高度取错点。** `carrybox_x2_rewards.py:34–40` 和 `mdp/carrybox_walled.py:276–281` 把 `robot.body_pos_w[:, head_link]` 的link原点当成实际头部位置，直接套X2的头高门槛。实际G1 USD的head_link质量中心在局部z=0.449869m，头部视觉范围z=0.324796–0.530573m；固定关节的link原点却接近腰部。200步补充回放中，279个age≥9的抱箱样本里，head原点相对root平均仅高0.000161m，94.27%的样本因原点≤0.8m被standup门槛拒绝。当前standup的头高0.8/目标0.85及fallen的头高0.4均判断了错误物理位置。应统一取经过link四元数变换的实际头部参考点（例如资产COM/明确头部几何点），并重新审视G1阈值；不能简单改名字或随意降低阈值。这个错误不等于相机光线位姿错了，当前相机使用独立已配置的安装偏移。[实际USD与回放证据](head_frame_audit.json)。

1. **warm-start没有健康基础技能。** [旧run4101–4200轮](warm_start_source.json)平均回合65.09步、tipped90.17%、成功指标0、style0.001179。`warm_start()`还继承整个策略的`log_std`，旧动作std约1.58。模型能加载、参数有限，不等于适合作为finetune起点。本次新run的model0在行走初始化回放平均3.82步倾倒。
2. **专家示范与任务限位惩罚矛盾。** [实际G1 USD限位核对](reference_soft_limits.json)：双膝硬范围约[-0.087267,2.879800]rad，0.9软限位下限为+0.061086rad；抱箱示范膝角均值约-0.0861/-0.0876rad。完全按照示范就产生平均1.479的限位代价，乘0.02控制周期和0.75任务混合后是每步-0.02219，而AMP加权奖励上限仅+0.01。11段行走示范同项平均代价0.480–0.859。扩大action clip到9只解决目标表达范围，没有解决奖励冲突或动力学跟踪。
3. **混合RSI掩盖前半程失败。** 默认reset比例80%行走、0%拾取、20%直接抱箱，是reset次数比例，不是rollout样本比例。行走回合只有3–4步，不能形成AMP的10帧窗口；直接抱箱回合长得多，几乎占满有效窗口。不能用总体AMP valid≈97%证明行走技能有足够有效模仿样本。pick_up仍占专家采样40%，却没有pickup RSI回合提供局部练习机会；这个X2 finetune配方未经基础技能验收就用于当前G1起点。
4. **训练时的AMP信号很弱。** 当前判别器对专家窗口平均得分约0.999998，但对正式训练策略style约0.0023。判别器loss接近零代表容易区分，并不代表模仿成功。短回放中，同一最新checkpoint的直接抱箱确定性动作style约0.604，训练采样动作约0.0102；这是实际噪声影响线索。并非所有推理行为都被判成零分，也不能仅据loss宣称数据加载错误。专家小噪声探针没有显示0.02rad关节噪声必然导致零奖励。
5. **奖励可以支持局部行为。** 近箱walk固定1.5；地面箱中心0.13m时，carryup的高度项也有约0.325正奖励，无需抬起；直接抱箱初始化更容易获得较高walk/carryup。已观察到“直接抱箱有效、行走失败”，但未证明每个局部奖励项的独立因果贡献。

[拾取示范高度](pickup_reference_heights.json)还表明，三段中两段接触时箱中心约0.368/0.425m（对应支持台约0.243/0.300m），第三段约0.130m接近地面任务。数据并非全部来自同一地面拾箱条件；该差异是后续课程/数据审计项，不能声称数据全部不可用。
