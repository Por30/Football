# 基于本次对照的重构边界

这是后续实施依据，本轮没有执行重构或启动训练。详细差异、源码和CPU证据见[完整报告](README.md)。

当前问题不是缺一个阈值，而是多套语义叠加：PhysHSI碰撞/reset、X2奖励门控、G1重新标定、深度actor、独立AMP优化器。建议以已有独立wall10为候选起点，先补齐本次识别出的偏差，再验收；保留wall5及其checkpoint回放，避免继续让一个Gym ID包含越来越多互不兼容的配方。

## 必须先写清的目标

用户目标保持为“深度找箱→接近→抓取→抬起并保持”。不因为源实现提供箱子真值，就把真值放回actor；critic、AMP和监督标签保持训练专用。

源PhysHSI搬运、目的地、放下、松手奖励不直接迁入此目标。必须区分两个层面：恢复底层控制/优化语义；针对删去goal后的任务重新定义奖励闭环。不能删除relocation后，继续把“只有放下成功才开启”的standup当抱箱目标。

## 当前 wall10 在正式使用前应补查的具体点

1. 首步加速度baseline：源post_step会更新到reset后的qdot；wall10强制0会对RSI初始qdot额外处罚。应先用一个已知qdot的reset样本核对数值。
2. AMP坐标：专家与在线一律使用选定frame；腰旋转时单独验证五端点、box、lin/ang、rot6，不只用直立零腰姿态。
3. 箱尺寸：源实际arange网格576，wall10整数网格441。选择是严格复刻“有效行为”还是修复源浮点越界，必须写清；射线与碰撞用同一个每env尺寸。
4. 数据：wall10依然用静止hold和删减后的15段，不代表恢复了19段源专家；不同任务目标可以保留删减，但必须使用不同manifest身份。
5. 时序平滑：源是状态插值/外推，深度分支目前也混合图像；负α可能生成超传感器范围的混合图像，需观察损失与梯度，不能只看shape通过。
6. 物理：robot 8/0不等于场景中box/platform也8/0；contact/rest offset、惯量、摩擦合成与实际碰撞shape需运行时dump核验。
7. 当前CNN执行块8192与逻辑随机块256已有性能分支自己的回执：34项CPU、4096×100约18.49 s/轮、4096×24约4.41 s/轮，源码hash与本轮一致。继续使用时应保留这组配方身份；短测通过不代表长期训练和抓取收敛。

## 最小分层验收顺序

先做接口与物理检查，再作短训，再正式训练。每层都保留原版及当前失败证据，不把调参后“能启动”当“任务已学会”。

1. **纯CPU契约**：关节映射、单位、旋转重建、动作clip/延迟边界、原始文件hash、AMP同姿态同特征、奖励边界连续性、reset来源/终止标签。
2. **少量环境物理**：相同初态默认目标保持、参考控制、无扰动/既定扰动；核对足底穿透、自碰撞、实际effort/饱和、三pickup参考手箱接触与平台支撑。不先拿随机策略站不住认定PD错误。
3. **训练单步闭环**：rollout→GAE→PPO/AMP→checkpoint→严格恢复→actor导出；terminal数据来自reset前，本环境reset不污染其他环境。
4. **正式规模性能**：4096、目标rollout长度、完整深度遮挡，测采样/深度/更新/保存耗时及峰值显存；按transitions/s和固定采样预算比较，不只按秒/iter。
5. **行为验收**：default/loco/pickup/hold分别记录episode长度、终止原因、距离、双手接触、箱底高度、root速度、动作/力矩饱和；地面起点成功单独统计。四格录像包含全部reset，不把空中RSI持箱算地面拾箱。

只有动态对照才能把“不同”提升为“导致失败”。本报告支持重构范围与优先级，不支持认定某一个参数是唯一病因。
