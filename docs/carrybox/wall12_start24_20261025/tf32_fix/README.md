# wall12 大批量 TF32 尺寸对称判定修复

首个4096环境正式run在首轮PPO/AMP联合更新抛出非有限损失，未生成checkpoint。日志、启动身份和原验证源码hash保存在父目录`attempt1/`及原logs路径。

`train.py`启用CUDA matmul TF32。原尺寸置换`einsum('kij,nj->nki', abs(S), sizes)`在8192行大批量时使用TF32，尺寸舍入误差超过`atol=1e-6 m, rtol=1e-5`，甚至恒等置换也不再通过尺寸相等判断。所有旋转候选被masked_fill为inf，辅助旋转损失随之为inf。16环境短测使用92样本训练块，没有触发此GEMM路径。

同一4090独立复现：TF32关闭的92/8192行、TF32开启的92行均没有空候选；开启TF32的8192行则8192行全空。

修复仅把尺寸的轴置换换成精确索引：`sizes[:, rotations.abs().argmax(dim=-1)]`。置换是索引操作，不需浮点矩阵乘法。原尺寸容差、正旋转集合、损失和系数保持，全局TF32不变，没有屏蔽inf、过滤样本或改为较小训练批。

验证：44项既有CPU回归通过；新增CUDA检查覆盖92/8192行和TF32开关，逐元素与独立float64数学定义比较，检查4/8/24候选数及接近但不相等尺寸。所有配置损失/梯度有限，修复后空候选为0。CPU和CUDA实际回执见`receipts.json`，详细输出见`cpu.log`、`cuda.log`。

正式4096环境重启和至少12轮运行检查由父级启动任务记录；本文件的局部数值回归结果不是任务收敛或位姿精度证据。
