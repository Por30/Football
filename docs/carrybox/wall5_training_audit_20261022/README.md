## 1. 优先级高：力矩惩罚与PhysHSI的尺度相差很大

当前注册的是原始力矩平方：`-1e-4 * sum(tau²)`，见 [carrybox_walled_env_cfg.py](../../../source/perceptual_ball/perceptual_ball/tasks/manager_based/perceptual_ball/carrybox_walled_env_cfg.py:102)。本地PhysHSI的 [carrybox.py](/home/cao/PhysHSI/legged_gym/legged_gym/envs/g1/carrybox.py:1768) 是 `-1e-4 * sum((tau / kp)²)`。两边权重相同，但被惩罚的量不同；现有kp为20–300，单关节对应400–90000倍。当前历史配置继承X2任务奖励，不能仅因与PhysHSI不同就称为移植笔误。

固定model200、64环境、采样动作回放256步，loco RSI组7397个transition，按相同状态/力矩计算：当前力矩惩罚每步 **−0.023425**；若只将公式换为PhysHSI形式则为 **−0.000001221**，约 **19185倍**。这是同批状态上的公式对比，不是修改奖励后重新训练的结果，也不意味着所有行为的回报都会增加同样倍数。

正式训练302–401轮每个空手控制步的平均奖励贡献（均已含weight和dt=0.02s）：

| 项目 | 每控制步贡献 |
|---|---:|
| walk_task | +0.01620 |
| torques | −0.01875 |
| action_rate | −0.01280 |
| 空手全部task合计 | −0.03218 |

力矩一项已经超过walk奖励，连同动作变化惩罚约为walk的1.95倍。`action_rate`与PhysHSI均是原始动作差平方，本次未发现其公式错误；问题是当前策略下整体奖励尺度。没有早终止惩罚时，持续负回报可能产生缩短回合的激励，但尚不能证明策略已经通过某种单一机制利用它。**建议先单独处理力矩项的语义与尺度，验证空手奖励/回合长度，再调整其他项。** 不宜直接将所有不同之处同时替换。

## 2. 优先级高：AMP判别器饱和，当前未提供足够的运动引导

正式日志302–401轮，expert loss平均0.000408、policy loss平均0.004939，style平均0.020804。固定model200的2048条专家窗口，style均值0.999867；loco策略回放为0.02823（采样）/0.02828（均值）。这是明显的专家/策略分离现象，不能据此确定是判别器训练过强、初态分布差异还是策略先失稳导致。

排查了两个具体疑点：

- **AMP特征对齐：** 256个未加扰动的参考状态写入仿真，逐项比较60维专家/仿真特征。关节角完全一致，根高度、线/角速度、rot6、箱子位置误差最大约1.82e-6；末端位置平均绝对误差0.544mm、最大3.613mm。未看到关节顺序、坐标系或厘米级末端错位。该检查不代表参考速度与随机化reset速度相同。
- **重复初始帧：** 当前短回合确实大多不足10帧，但对同一批专家窗口只替换重复前缀，全部10帧重复时style仍为0.987742，正常历史为0.999867。**这次证据不支持“重复历史本身足以导致AMP接近0”这一解释。** 不建议仅凭短历史比例就把早期transition全部屏蔽。

应继续分开量化reset速度/关节扰动产生的分布差异和策略动作造成的偏离，再决定AMP采样或优化改动；不能把判别器饱和直接当成已经定位的代码bug。
