# 敏捷回踢研究主线：IROS 2027

更新：2026-09-19。状态：研究候选与诊断草案；Claim Lock、Design Lock 均未冻结；本次没有运行训练或评测。

## 已确认目标与证据边界

承接根目录 `Codex_Handoff_X2_Agile_Return_IROS2027 (1).md`。目标是用机载深度历史和本体感知，应对传入的运动足球，完成一触回踢、逐步加入指定回传区域，并恢复到可处理下一球的状态。来球速度与出球速度必须分别报告。部署 actor 不读取仿真球真值或外部光捕；仿真真值可用于 critic、奖励、辅助监督与离线诊断。

用户于 2026-09-19 确认以 **G1** 为平台，当前仓库是 G1 29-DoF。X2 交接文档作为历史设计参考，不将 G1 结果归到 X2。相机、机载算力、实机条件、GPU 预算尚未确认。

证据分层：

- 用户报告：原基础方案能训练 0.4–0.8 m/s 来球，踢后不稳，提高来球速度后失衡。尚未复测，不能当成已测性能上限。
- 源码核验：G1 基础版与 Soccer v2 两个注册入口；解析球体深度无地面/自遮挡；两段左右踢球 AMP 数据；v2 为站姿初始化、双 critic/AMP、噪声与随机化。
- 文件核验：基础版存在 `model_27000.pt` 等产物，v2 当前最高编号为 `model_2.pt`。编号不代表性能，checkpoint 与历史配置/源码匹配尚需核验。
- 未取得：统一评测成功率、真实脚球接触记录、完整回合成功率、恢复时间、机载延迟和实机结果。

## 研究问题与候选机制

类型：MIXED（以学习控制技术为主，配合能区分失败机制的评测）。一句话主线：从延迟、间歇可见的深度观测中，学习与身体准备状态相匹配的接触时间窗口，提高有限准备时间下的完整回合成功率。

候选假设 H1：在相同训练预算、奖励、参考动作与传感条件下，联合表示来球到达时间和身体可执行时间窗口，比仅回归当前球状态更有利于短准备时间下的回踢与恢复。这是待验证假设，不能作为已成立贡献。

最小架构候选分两步实施，避免把多个改动收益混在一起：

1. 匹配基线：现有深度 CNN latent 与本体历史、过去动作、观测年龄及有效性融合；所有对照使用相同输入与近似容量。是否需要 GRU/TCN 由延迟诊断决定，暂不选 Transformer。
2. 核心候选：融合表征输出每只脚、若干未来时刻的接触可执行性/成功概率，并将该表征供 actor 使用；当前球状态回归保留为共享辅助任务。actor 仍直接输出关节动作。

关键未决点：球到达时间可从仿真轨迹构造标签，但“该身体状态来得及执行且能恢复”不能用球距/球速冒充。先记录闭环执行与恢复事件；若需要状态分支 rollout 估计可执行窗口，须记录策略依赖、额外采样预算和失败标签，并防止标签泄露到部署输入。在标签可识别性确认前不实施该头，也不声称得到物理可达性保证。

可证伪条件：若增强融合/普通延迟随机化已解释全部收益，或者窗口头只降低预测误差而不提高匹配条件下的完整回合成功率，则 H1 不获支持；若主要失败来自力矩/速度饱和或不可靠接触仿真，先修正工程瓶颈，不能把其收益归为感知机制创新。

## 先做的诊断与公平对照

这部分是预实验草案，正式阈值、样本量和分析在看结果前另行冻结。

| 步骤 | 操作 | 能回答的问题 |
|---|---|---|
| D0 基线身份 | 保存 checkpoint 校验和、对应 params、代码快照与依赖；检查旧 checkpoint 能否在对应配置下加载 | 现有结果是否可复现，是否误用新版环境 |
| D1 测量有效性 | 增加 serve_id 与仿真时间，区分 reset/re-serve 和物理碰撞；检验被动反弹/躯干碰球；记录真实接触与脚距代理的一致性 | 当前“成功”是否确为有效踢球 |
| D2 低速起点 | 固定一组未用于训练的来球；先做 0.4/0.6/0.8 m/s，再按失败位置扩展 1.0/1.2/1.6/2.0 m/s | 性能随实际到达速度如何变化 |
| D3 感知时序 | 同一来球和初始身体状态下改变首次可见时刻、传感延迟、遮挡；分别记录采样时间与送入策略时间 | 高速失败来自速度本身还是准备时间不足 |
| D4 身体与恢复 | 单独比较站稳开始和 RSI；记录首次准备、首次有效接触、失衡和恢复时间 | 未准备好、踢空、接触后失衡分别占多少 |
| D5 物理分辨率 | 仅对代表性高速失败以更小物理步长复测，保持 50 Hz 控制和相同任务条件 | 接触漏检/数值误差是否主导失败 |

先记录基础版原始指标，并在独立评测中增加严格指标；不直接覆盖旧奖励。Soccer v2 可作为候选工程基线，但它已有多项同时改动且本地仅见短跑产物，不能直接认定优于基础版。

受控对照优先为：同等融合/记忆容量、同等延迟随机化的强基线；增加未来球状态预测的对照；再增加身体条件的接触窗口头。比较时统一 actor 信息、恢复奖励、数据与优化预算。不得只对新方法加恢复奖励或更真实相机。若使用真值诊断策略，必须另行训练、明确标为不可部署对照，不将现有深度策略直接换输入后比较。

第一版日志至少包含：serve_id、seed、初始/实际到达球速、采样/可用观测时刻、初始身体状态、脚球与非脚接触、球目标误差、接触前后 root/关节状态、力矩/速度限幅、结束原因、恢复是否完成与耗时。

可用准备时间采用独立于策略是否成功接触的基准：同一来球在未受机器人扰动时到达预定义拦截截面的时间，减去首个有效观测送达策略的时间。截面与有效观测规则预先固定；无有效观测、未到达截面和不可达来球单列原因且保留在整体分母，不能只用成功接触样本计算反应时间。

完整回合成功需同时满足有效脚球交互、目标区域/出球速度要求和规定期限内恢复。具体目标区域、恢复姿态/速度阈值及持续时间待预实验后、正式测试前冻结。接触率、方向误差、跌倒率、恢复耗时、连续来球成功率均单独报告；条件于成功接触的误差不能代替全部发球的成功率。初始发球速度不等于运行中球速。

## 相关工作初筛（2026-09-19）

- [RoboNaldo 论文](https://arxiv.org/html/2606.11092v1)与[官方代码](https://github.com/OpenDriveLab/RoboNaldo)：已经覆盖运动来球、接触触发、机载感知和 G1 实机；其 Stage 3 以速度指令和 kick trigger 连接高层与低层。候选差异只能围绕身体条件下的时间窗口及延迟鲁棒机制验证，不能写“现有方法只踢静止球”。优先威胁：高。
- [Vision-Based Dribbling](https://arxiv.org/abs/2607.12702)：摘要已包含时序深度编码器、强化学习与特权表征。仅使用深度历史或增加视觉辅助监督不充分；全文核查待做。
- [CyboRacket](https://arxiv.org/abs/2603.14605)：摘要包含机载视觉、未来轨迹预测和全身击球执行。仅声称未来球预测与全身控制结合也不充分；全文核查待做。
- RoboNaldo 相关工作中出现的 HumanX、PAiD，以及 [Learning Agile Striker Skills](https://www.cs.utexas.edu/~pstone/Papers/bib2html/b2hd-zifan_xu_icra_2026.html)列入后续全文排查；本轮不据二手描述归纳其缺陷。

初筛结论：问题设置和若干模块与已有工作明显重合；具体窗口机制的差异尚未审计完成。新颖性状态为 INSUFFICIENT_EVIDENCE，不提出“首次”主张，也不判断录用概率。
